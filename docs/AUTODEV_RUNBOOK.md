# Probably-TAU — автономная очередь по ролям (пилот v1)

**Статус:** предложение координатора 00 в ветке `ops/autodev-scheduler`, не слито в main.  
**Цель:** развивать игру через GitHub, пока владелец не у компьютера. **Пять автономных расписаний активированы 14.11.2026:** 01, 04, 02, 03, 05. Это план запусков, а не доказательство, что Unity или CI успешно работают.

## Как это технически устроено
- Используются **отдельные автоматические задачи ChatGPT с зафиксированными промптами роли**, а не прямое пробуждение существующих чатов 01–05. Эти запуски обязаны перечитывать GitHub.
- Частота **каждой задачи — раз в 100 минут** (RRULE:FREQ=MINUTELY;INTERVAL=100, что реже предельного ежечасного запуска одной задачи). Старт различных ролей разнесён на 20 минут; это время *запуска*, а не обещанная длительность выполнения/завершения. Непрерывный 20-минутный график не гарантирует отсутствие наложения исполняющихся задач.
- На текущем плане допускается максимум 5 активных расписаний, поэтому роли 01–05 запускаются автоматически; координатор 00 не имеет собственного таймера. QA 05 передаёт ему сводку, а 00 проверяет вручную по запросу. Если задача недоступна или GitHub недоступен, пометить BLOCKED, не объявлять успех.
- Для полноценной сборки Unity нужен настоящий Unity Editor и подходящая среда тестирования. GitHub-коннектор сам по себе не компилирует Unity.

## Перед каждым запуском — строгие preflight gates
1. Загрузить `main`, `AGENTS.md`, `docs/CHAT_WORKFLOW.md`, `docs/DECISIONS.md`, текущие Issues/PR/handoff. До слияния ADR-C0-001 смотреть PR #14 и C0-v2 в PR #9.
2. Проверить, что предыдущее выполнение этой роли завершено и нет незаконченного конфликта в собственной ветке. При наличии конфликтов или чужого блокера сначала зафиксировать состояние, не force push.
3. Выбрать **одну ограниченную, реально выполнимую задачу** в своей подсистеме, связанную с открытым Issue.
4. Писать только в `feature/<owned>`, а не в main; не трогать чужие директории и контракты. Ни один агент не создаёт второй GameState или альтернативный ledger.
5. Тестировать тем, что доступно. Если Unity Editor отсутствует — explicit NOT RUN, не «green». Если нужна локальная сборка/секреты — Issue BLOCKED.
6. Обновить PR или создать его, приложить commit SHA, дифф, тесты, риски, следующий шаг. Обновить `docs/handoffs/<role>.md` в собственной ветке.
7. **Не merge**, не закрывать чужие Issues, не менять branch-protection, не выполнять удалений веток или чужого кода. Не увеличивать денежные расходы на API/CI без разрешения владельца.

## Blocking conditions
- Core C0 архитектура v2 **разрешена к реализации**, зафиксирована в PR #14, но она не интегрирована в main. До появления реальных C# DTO NPC/Save реализуют только безопасные независимые части.
- Если нужной ветки нет: NPC может создать feature/npc-4 от main только для проектирования, а runtime — после интеграционного определения типов.
- Не проверено наличие Unity Editor/dotnet в execution environment.
- Не считать HTML-макет Unity-игрой, draft JSON исполняемой схемой, тест-план выполненным тестом.
- При отсутствии доступного code-write/run environment — зафиксировать blockers, не имитировать коммиты.
- Если на role PR уже есть BLOCKED от QA/00, сначала устранить блокер вместо следующей функции.

## Журнал следующего шага
GitHub Issues и docs/handoffs — единый источник контекста; каждый запуск должен написать «выполнено/не выполнено» и точный следующий шаг. QA 05 в конце каждого 100-минутного цикла делает сводку PR, CI status, зависимостей и блокировок для координатора 00; сам координатор проверяет её при ручном обращении. Шестой автозапуск 00 сейчас не создан по лимиту плана. Никакой труд «в фоне» не обещается вне пяти созданных расписаний.

## Ограничение ChatGPT Automations
Scheduled ChatGPT prompts **не являются гарантированно полноценными кодовыми агентами с Unity Editor, постоянным клоном репозитория или возможностью вызвать существующий чат**. Проверка фактической способности запланированного запуска пушить код обязательна после первого срабатывания. Для действительно непрерывной автономной реализации можно позже перейти на GitHub Actions + отдельный агентный раннер/облачную среду со специально выданными токенами и лимитами.
